## Classification rule

This inventory classifies by **actual authority and behavior**, not by directory name. `SPLIT` means the current file/module carries multiple v3.1 authorities and must be separated before cutover. No item in this document authorizes deletion, archive, or merge.

Canonical owners:

- src/unityagent/policy: defines user/security/approval/evidence/risk rules.
- src/unityagent/context: materializes the current model input.
- src/unityagent/orchestration: decides graph/subgraph/node/gate/local semantic-loop flow.
- src/unityagent/runtime: executes actions and enforces current-run safety through the Execution Harness Plane.
- src/unityagent/persistence: owns durable state/checkpoint/session/memory/evidence truth.
- src/unityagent/operations: observes production and controls it externally through src/unityagent/policy/Approval.
- eval: measures, attributes, reports, and proposes; it never directly mutates production modules.

## High-risk findings discovered by content review

1. `ContinuationController` is not a pure Local Loop component. It also enforces budget/quota, worker leases, health/human gates, and quota accounting. Blind move to `src/unityagent/orchestration/graph/local_loops` would recreate a giant loop controller.
2. `ExecutionOrchestrator` invokes subprocesses with hard timeouts, enforces path/scope rules, retrieves Memory and Ix data, captures evidence, and emits state patches. It cannot be owned solely by Orchestration.
3. `LayeredMemoryController` stores raw evidence under `Evidence/raw` and memory under `STATE/memory`. v3.1 requires Evidence and Memory to be separate authoritative concepts.
4. `CodexProductionAgent v2` currently reads `.ai/harness/task-contracts`, aggregates gates, writes evidence, and assigns failure classes. The new Runner must execute and emit typed facts; eval must own grading/attribution.
5. `BehaviorEvalAdapter v2` already consumes canonical `metrics.json.changed_paths`; this is the preferred migration seam. Do not replace it with diff-text reconstruction.
6. The Unity Editor package’s “Artifact Graph” is a dependency/data graph, not the agent-control Parent Graph. Its scanner is a Runtime Unity Harness capability whose output can feed src/unityagent/context/Investigation.
