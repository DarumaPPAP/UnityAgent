# P0安全性Regression 実装計画

**Goal:** 現行main `32a3a3338be0db7a7f60b1ed62c0413800a6e989` のApproval、Mutation、Persistenceの実経路を既存unittestで保護し、PRとCIで検証する。

**Architecture:** 既存の3つのRegression Moduleを拡張する。実署名はArtist AuthorityのHTTP/HMAC境界、Dispatch抑止はControl PlaneのArtist実行入口、Mutationは実FileProviderと実FS差分、RecoveryはCheckpointStoreとevaluate_resumeを通す。新規Framework・依存・Fixture基盤は追加しない。

**Tech Stack:** Python unittest / TemporaryDirectory / subprocess / 既存CI。

**Spec:** ユーザー指定のP0 3領域。実Unity Editor、PlayMode、Deviceは別P1。Merge、Release、Tagは禁止。

## 判断と制約

既存の局所Guardだけを増やす方法では接続の欠落を検出できない。全Unity E2EではP1の環境に依存する。そこでP0の実署名・永続化・FileProviderを実行し、外側のEditor観測とContext準備を代替するケースはその境界を明示する。Scope外への拡張や新しい認可方式は導入しない。

Policy provenance: `src/unityagent/policy/user/user-policy.yaml`、`src/unityagent/policy/approval/approval-policy.yaml`、`src/unityagent/policy/evidence/evidence-policy.yaml`。Repositoryのtest-lifecycle/test-qualityを適用する。

## 手順

- [ ] Approval: 実登録・approve・Resolver・Authorityを使用。正常署名、署名不正、別Project、期限切れ、取消、単回消費と実Dispatch前停止を検証する。
- [ ] Mutation: 実FileProviderの正常変更と独立したFS差分を照合。Traversal、Scope外、禁止優先、誤Project、古いpreimageによる拒否と元ファイル保護を検証する。
- [ ] Persistence: 実状態からCheckpointを作成し、Resume判定とrestoreを検証。破損、Run取り違え、Evidence改竄、外部Action実行中、異常終了を故障注入する。
- [ ] 不具合が再現した場合は、意図した修正前FAILを保存して最小修正し再検証する。
- [ ] 全Regression、既存Smoke契約、Static、Packagingを確認し、故障注入の検出力・未達・BLOCKED_NOT_RUNを対応表に記録する。
- [ ] 日本語PRを作成し、同じheadのCIとActions Evidenceを照合する。

## Review Focus

無条件拒否を正常系で検出する。不正署名以外の前提を成立させる。拒否時に対象ファイルと消費状態を保護する。Resumeは現在定義との互換性とEvidenceの同Run性を検証する。異常終了後に部分書込みを成功状態として扱わない。

## 実装時の判断記録

CheckpointのEvidenceは子Run unionを許容する既存Task DAG契約に合わせ、親Run一致を要求せず各Recordの実整合性を検証する。子Run unionの正常系を追加した。実Runtimeの子Processで適用後Scopeを検証し、単独Guardの手動接続だけに依存しない。

再レビューで判明したState契約違反による部分復元とDispatch入口の検出漏れは、正本State Schemaの共通検証および実Broker→FileProvider.executeの統合テストで修正する。故障注入は既存CIのunittest Stepで実行し、通常回帰と期待Assertion失敗を別ログへ保存する。
