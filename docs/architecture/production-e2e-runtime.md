# Production E2E Runtime additions

Approved requirements: [Production E2E Goal](../decisions/production-e2e/approved-goal.md). This document describes implemented host paths, not a claim of Production verification.

## Task execution and QA

`UnityAgentControlPlane.execute_tasks(tasks, run_id=..., definition_fingerprint=..., task_parameters=..., resume=False)` executes the existing DAG planner's dependency batches through the existing `execute` facade. A Task carries `id`, `workspace`, `goal`, `depends_on`, `write_set`, `resource_claims`, `entry_request`, and immutable `required_gates` mapping gate IDs to required evidence types. Runtime parameters remain host-owned; Entry cannot select a Provider.

Required gates cannot be removed during resume. Evidence must match the actual Task Run and effective Definition fingerprint. QA's deterministic `assess_task` does not dispatch tools or relax acceptance. Existing Performance reasoning is preserved under `qa_subagent`, with `performance_subagent` as an explicit input alias.

The initial Scheduler deliberately executes serially, including batches proposed as parallel. Parallel speedup is `unmeasured`. The single-Task `execute` Fast Path remains unchanged.

A Task may declare a fixed list of `repair_candidates` (Entry v2 requests), with `semantic_repair_limit` defaulting to the goal's initial candidate of 2. This is a Task contract value, not an infinite retry policy. Existing `RuntimeBudgetLedger` and `decide_semantic_loop` enforce it. Required gates stay fixed across candidates. Repeating the same failure, unavailable observation, Policy/Approval refusal, and uncertain mutation side effects stop correction. Failed mutation Tasks require explicit side-effect reconciliation before another correction; the automated loop starts from verified read/analysis failures. Infrastructure retry remains inside the Broker and has its own budget. Task history records every handoff and semantic retry.

Run Checkpoints reference an immutable Task snapshot through existing Workflow State. Checkpoint restoration does not restore Unity assets. Resume checks Definition and Project content revisions and refuses an interrupted `running` Task until external effects are reconciled.

## Binary staging

`StagedAssets` permits FBX/image import sources only. It uses the existing Mutation Scope evaluator, stores original/generated bytes and hashes for assets and `.meta`, validates the whole preimage before writes, and refuses traversal, symlinks, corrupt backups and concurrent edits. It never writes raw `.unity`, `.prefab` or `.mat` files. The calling Runtime must hold the Project Lease and supply the trusted approval recheck.

This helper is not yet the full post-Editor asset rollback workflow. Newly generated importer metadata or other Editor changes invalidate the expected postimage and stop rollback. It does not infer ownership of an Editor-generated `.meta`, restore arbitrary user assets, or use Git reset.

## Blender MCP

```
unity-agent rock plan --project-path PROJECT --state-root EXTERNAL_STATE --job-id rock-g1
unity-agent rock approve --project-path PROJECT --state-root EXTERNAL_STATE --plan-id PLAN
unity-agent rock apply --project-path PROJECT --state-root EXTERNAL_STATE --plan-id PLAN --approval-ref APPROVAL --mcp-executable INSTALLED_SERVER
```

The plan exposes the entire reviewed deterministic Python template. Its digest, project revision, Definition revision, approval expiry/revocation, and staging scope are checked before the MCP tool call. The adapter accepts no caller-supplied Python. JSON-RPC initialization/tool discovery precede execution. Creation additionally requires an observed remote Blender identity from `get_scene_info.structuredContent.blender_session_identity`. An MCP client/process UUID alone is not a Blender identity; a server that does not supply this observed binding remains unavailable for mutation. Session locks use the Host's shared UnityAgent cache namespace even when callers use different Persistence roots. The fixed template creates one named mesh, UVs and material, then exports FBX plus an artifact manifest. No external generator is called.

Blender Session jobs use Persistence and the existing lock primitive. They do not hold the Unity Project Lease during generation. A submitted/uncertain Job is never automatically resubmitted. Session changes require reconciliation. Artifact checks cover binary FBX presence/size, hash, positive geometry, scale, UV and external texture dependencies. Protocol/server identity is retained; addon version remains `unmeasured` until an actual server observation supplies it.

`rock apply` returns only artifact-creation completion. `verified: false` and `unity_import: BLOCKED_NOT_RUN` remain explicit. The G1 Editor harness consumes that artifact separately. The complete Production Runtime import/Prefab/Scene/QA/rollback handoff remains unfinished.

Optional Doctor supports `--product blender_mcp --product unity_cli_loop`. Missing tools do not disable core capabilities. Presence on PATH is only `installed`; protocol, binding, revision and execution capabilities remain unknown until live probes. Setup plans are `manual_required`; no package installation/update is performed by these new adapters.

## Unity CLI Loop V3

The optional `editor.hot_reload` capability supplements existing CLI/Pipeline Providers. `hot-reload plan/approve/apply` binds exact Source hashes, Project revision and a reviewed local `uloop-project-runner` executable hash. Calling the global dispatcher could download/update a runner; this adapter uses the pinned installed project runner directly.

Apply checks Editor readiness and Play state, calls `hot-reload --files ... --compile-on-skip off --project-path ...`, and rejects partial/Skipped/Failed/empty/Compile-fallback results. Source hashes are checked before and after. Runtime patch success does not satisfy normal Compile, Play behavior, or QA acceptance. CLI apply exits nonzero while these required gates remain unobserved. Removing runtime patches is not asset/source rollback.

## Comparison and acceptance

`eval/production_e2e/compare_iterations.py` validates paired identical Task/Environment trials and reports median/nearest-rank p95, completion rate, retries, fallbacks, token totals, runtime side effects and regression rate. Missing token measurements stay `unmeasured`; fewer than five pairs do not support the improvement recommendation. Caller-supplied samples require durable evidence review separately. Nothing auto-enables Hot Reload.

`tools/production_e2e/collect_evidence.py` keeps Production, Blender MCP, compile, Editor import, render, visual review, rollback, lease conflict, video decoding, Hot Reload comparison, G2 and G3 separate. A missing gate becomes `BLOCKED_NOT_RUN`; fixture-only success cannot establish Production success.
